# Experiment / Checkpoint / Log Directory Protocol

## Scope and sources

Read-only audit based on:

- `README.md`
- `config/*.yaml`
- `stages.py`
- `cvt2distilgpt2_mimic_cxr_chen.py`
- `cvt2distilgpt2_iu_x_ray_chen.py`
- `tools/metrics/report_logger.py`

Important limitation: experiment directory construction, checkpoint callbacks, and logger setup are mostly delegated to external `dlhpcstarter`. This repository receives `exp_dir_trial` and uses it, but does not define how it is constructed.

```text

    └── test_reports_epoch-<epoch>_<DD-MM-YYYY_HH-MM-SS>.csv
```


## 2. Checkpoint locations

There are two checkpoint categories.

### A. Shared model zoo / external checkpoints

Controlled by config field:

```yaml
ckpt_zoo_dir: /data/lhy_data/Cvt2distillgpt2/checkpoints
```

Used for:

- CvT warm-start checkpoint:
  - `<ckpt_zoo_dir>/CvT-21-384x384-IN-22k.pth`
- DistilGPT2 local Hugging Face files:
  - `<ckpt_zoo_dir>/distilgpt2/config.json`
  - `<ckpt_zoo_dir>/distilgpt2/tokenizer.json`
  - `<ckpt_zoo_dir>/distilgpt2/pytorch_model.bin`
  - `<ckpt_zoo_dir>/distilgpt2/vocab.json`
- CheXbert checkpoint:
  - `<ckpt_zoo_dir>/stanford/chexbert/chexbert.pth`

README examples also mention task checkpoints under `checkpoints/mimic_cxr_jpg_chen/...` and `checkpoints/iu_x_ray_chen/...`, but current test YAMLs use absolute experiment checkpoint paths.

### B. Experiment training checkpoints

Controlled by:

- `exp_dir`
- `exp_dir_trial` from `dlhpcstarter`
- `monitor`
- `monitor_mode`
- `test_ckpt_path`

Testing checkpoint resolution in `stages.py`:

```python
ckpt_path = get_test_ckpt_path(
    args.exp_dir_trial,
    args.monitor,
    args.monitor_mode,
    args.test_epoch,
    args.test_ckpt_path,
)
write_test_ckpt_path(ckpt_path, args.exp_dir_trial)
model = TaskModel.load_from_checkpoint(checkpoint_path=ckpt_path, **vars(args), strict=False)
```

## 3. Best model / latest model naming

Visible checkpoint examples use PyTorch Lightning checkpoint names:

```text
epoch=42-step=521289-val_chen_cider=0.431418.ckpt
epoch=11-step=2076-val_chen_cider=0.444897.ckpt
epoch=8-val_chen_cider=0.425092.ckpt
epoch=10-val_chen_cider=0.475024.ckpt
```

Observed naming components:

- `epoch=<n>`
- optional `step=<n>`
- monitored metric name and value, e.g. `val_chen_cider=0.431418`
- `.ckpt`

Best checkpoint selection uses:

- `monitor: 'val_chen_cider'`
- `monitor_mode: 'max'`

A `latest` checkpoint naming convention is not visible in this repository. Resume helpers are imported (`resume_from_ckpt_path`) but the training resume call is commented out.

## 4. Generated report location

Always generated by `ReportLogger` at:

```text
<exp_dir_trial>/generated_reports/
```

File pattern:

```text
<split>_epoch-<epoch>_<DD-MM-YYYY_HH-MM-SS>.csv
```

Where split is currently:

- `val_reports`
- `test_reports`

CSV columns:

```text
report,dicom_id
```

## 5. Metrics location

### Always-on metrics

Metric dicts are logged with Lightning:

```python
self.log_dict({f'val_{k}': v for k, v in scores.items()}, on_step=False, on_epoch=True)
self.log_dict({f'test_{k}': v for k, v in scores.items()}, on_step=False, on_epoch=True)
```

The visible source does not explicitly write a final `metrics.json` or `metrics.csv`. Persistent logger location is delegated to `dlhpcstarter` / Lightning.

### Optional metrics files

If metric save flags are enabled:

```text
<exp_dir>/predictions.csv
<exp_dir>/individual_scores.csv
<exp_dir>/bootstrapped_scores.csv
<exp_dir>/ce_class_metrics.csv
<exp_dir>/ce_class_metrics_2.csv
<exp_dir>/chexbert_outputs_<timestamp>.csv
```

Current model constructors do not enable those flags.

## 12. Recommended MedGemma-RRG directory alignment

To preserve original compatibility while adding modern evaluator outputs:

```text
outputs/<dataset>/<run_name>/
├── config.yaml
├── checkpoints/
│   ├── best.ckpt or adapter/                                  # MedGemma/LoRA-specific
│   └── latest.ckpt                                            # optional
├── generated_reports/
│   ├── test_reports_epoch-none_<timestamp>.csv                # legacy-compatible report,dicom_id
│   └── val_reports_epoch-none_<timestamp>.csv                 # optional
├── predictions.jsonl                                          # canonical rich MedGemma output
├── predictions.csv                                            # rich CSV with prediction/reference/image paths
├── metrics/
│   ├── metrics.json
│   ├── metrics.csv
│   ├── per_example_scores.csv                                 # optional
│   └── chexbert_outputs.csv                                   # optional
└── logs/
    ├── tensorboard/                                           # if used
    └── train.log                                              # if used
```

Compatibility requirement:

- Keep `generated_reports/<split>_reports_epoch-<epoch>_<timestamp>.csv` with columns `report,dicom_id` if any original-style consumer is expected.
- Also write richer JSONL/CSV because original CSV is insufficient for re-evaluation without references.
